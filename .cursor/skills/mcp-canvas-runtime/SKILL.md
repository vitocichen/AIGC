# MCP 画布执行层

当前对话 Agent 负责文字、图片、视频提示词、授权、执行核对、验收与记录。不调用 `runAgent`。不调用 `node:generateImage`、`node:generateAudio`，也不用画布供应商出图或出音频。只有用户针对本次明确的视频片段、模型、数量和次数逐次授权后，才允许使用 Toonflow 的 `listMediaModels`、视频节点 `node:setConfig`、`generateVideo` 或 `node:generateVideo` 调用内置视频模型。

仅在用户已选择“已有 Toonflow 并使用画布”，或完成 Windows 安装并确认使用画布后调用本技能。用户选择本地目录制作时改用 `../local-readable-runtime/SKILL.md`，不要因为没有 MCP 而降低、缩写或改写 `workflow` 成果。

## 每轮绑定目标

1. 先调用 `getAppState`，取得实际 `connectionId`、工作区绝对路径和当前 `canvasId`。
2. 多个连接时按用户指定目录匹配；仍有歧义才询问。
3. 目标项目未打开时使用 `openProject`，随后重新调用 `getAppState`。
4. 后续修改调用都携带实际 `connectionId`、`directory` 和 `canvasId`，防止用户切换窗口后写错项目。
5. 没有前端连接时停止画布和节点写入，说明需要启动客户端并打开项目；不得直接修改 `toonflowCanvas` JSON 作为替代。

## 节点操作

- 添加节点前查询当前画布支持的 `nodeTypes`，不猜类型名。
- 用 `findCanvasNodes` 查找目标；已知 ID 时用 `getCanvasNodes` 读取所需字段。
- 修改节点前用 `getNodeTools` 获取该节点真实函数及完整参数，再通过 `nodeTools` 调用。
- 文本成果写入文本节点的正式正文函数；写后回读节点输出或实际 `textPath` 核对。
- 提示词正文可以写入文本节点供查看。模型、比例、时长和分辨率记录在项目状态里。不得通过画布供应商配置出图；视频节点配置仅在用户逐次明确授权 Toonflow 内置视频生成后使用。
- 连接前读取源/目标端口，确认 handle 和数据类型；使用 `connectNodes` 建立真实引用。连线只表示画布上的素材关系，不触发 Toonflow 生成。
- 结构调整后只核对受影响节点和边；用户要求查看全图时再 `fitCanvas`，仅明确要求整理全图时才 `arrangeCanvas`。

## 阶段成果

`workflow` 产生的原文快照、剧本、资产表、生成方案、全片段表和视频提示词分别建立可查看的文本节点。已经生成的角色、场景、道具图片挂到图片素材节点；已经生成的视频挂到视频素材节点。只创建当前已确认阶段需要的节点；图片不创建供应商生成节点，视频生成节点只在用户逐次明确授权 Toonflow 内置视频生成后创建或复用。

版本更新保留已确认节点和已采用媒体；新候选建立新节点。不得覆盖旧节点后仍声称它是旧版本。

## 媒体执行与挂载

1. 图片和音频只由当前 Agent 的真实媒体工具生成，不调用 Toonflow 供应商。视频默认由当前 Agent 的真实视频工具生成；画布模式下，用户可逐次明确授权 Toonflow 内置视频模型。
2. 任何媒体生成前都展示对象与数量、模型、规格、完整提示词、参考顺序和次数。使用 Toonflow 视频模型时，报价或额度可可靠查询则如实展示；无法查询时标记未知，但不阻止已获授权的任务提交。
3. Toonflow 视频授权必须明确绑定本次片段、模型、数量和次数。一次授权只提交约定次数，不自动重试、不扩大批次、不切换模型；失败、超时或返回不明确时先查同一任务状态，额外尝试必须重新授权。
4. Toonflow 视频任务结束后记录任务 ID、实际模型、参数、状态和返回文件。不强制读取生成前后额度或计算损耗；接口主动返回额度信息时可据实附记。
5. 每个视频段必须带有 `workflow` 规定的 `【制片交接卡｜不发送给模型】`。提交供应商前必须剥离交接卡，只传模型正文。同一场戏的下一段提交前，先看上一段真实结尾。镜头按技能排。下一段的人物站位和背景要对上上一段，对不上就停住。跨场硬切、闪回、场景重建或时间跳跃不绑定上一场尾帧。下一段落地后再做同场拼接抽帧。站位错了或肩后再冒出一张完整的脸，停在这一场。
6. 生成工具返回真实文件后，先把文件放进当前工作区的可读路径，再用素材节点的 `node:setImage`、`node:setVideo` 或 `node:setAudio` 挂载。`path` 使用工作区相对路径，指向已经存在的文件。
7. 挂载后回读节点输出，核对路径和文件可读。回读失败不把预期路径说成已挂上。生成结果必须经过验收和用户采用，才能成为下游正式参考。

## 并发与恢复

- 客户端界面和外部 Agent 不能同时修改同一节点。每次写前回读，发生变化时合并或询问，不覆盖现场修改。
- 项目、画布或连接切换后重新发现状态，不复用旧 ID。
- 超时不能证明任务未提交；重试前先查状态，避免重复计费。
- 完成后区分“已保存”“已开始生成”“已生成”“已采用”和“已交付”。

## 跨 Agent 使用

本技能不依赖某一家语言模型。任何 Agent 只要能够：

1. 读取本仓库的 `AGENTS.md`、规则和 Skill；
2. 连接同一个 Streamable HTTP MCP 地址并携带 Bearer 凭据；
3. 调用上述 MCP 工具；

即可作为文字、图片和视频大脑执行同一流程。图片和音频仍用该 Agent 自己的媒体工具；视频默认使用该 Agent 工具，或在用户逐次明确授权后使用 Toonflow 内置视频模型。客户端切换时只更换该客户端的 MCP 配置，不更换工作区、技能和项目文件。

## 对话回执

首次绑定及每轮写入后，在对话框中报告当前连接状态、项目绝对路径、画布名称、本轮新增或修改的节点，以及媒体任务的真实状态。不得回显 Bearer Token，不得只说“已写入画布”而不告诉用户具体写到了哪个项目和画布。
