# Windows 画布安装

仅在用户选择“没有 Toonflow，但需要安装后使用画布”时执行。默认系统为 Windows；检测到其他系统时停止并确认，不套用 Windows 命令。

官方源码仓库：`https://github.com/HBAI-Ltd/Toonflow-app`。当前项目声明为 MIT；仍应保留安装包内原许可证和第三方声明。

## 安装前检查

1. 检查是否已存在可运行客户端、安装包或源码目录，避免重复下载和覆盖。
2. 检查 Windows 架构、可用空间、Git 和构建环境。
3. 不读取、复制或输出现有 API Key、MCP Token、模型凭据及其他用户隐私。
4. 已有安装能正常启动时不重装，直接进入 MCP 配置。

## GitHub 可访问

按以下优先级执行：

1. 优先检查官方 GitHub Releases，下载与当前 Windows 架构匹配的完整安装包，并核对发布来源、版本和可用校验信息。
2. 用户明确要求从源码安装，或 Release 没有合适安装包时：
   - `git clone https://github.com/HBAI-Ltd/Toonflow-app.git`
   - 已有仓库只执行安全的普通更新，不覆盖本地改动，不使用 `reset --hard`。
   - 读取该版本实际 `README.md`、`package.json` 和桌面端构建说明。
   - 安装其声明的 Bun 版本与依赖，再使用仓库当前真实提供的桌面打包命令；不得凭旧记忆猜命令。
3. 安装完成后启动客户端，打开目标项目，在设置中启用 MCP。

源码拉取成功不等于客户端安装成功；必须以可启动程序、版本信息和 MCP 状态作为验收依据。

## GitHub 不可访问或用户需要离线包

1. 优先使用当前环境中已存在、来源可验证的官方完整 Windows 安装包。
2. 没有安装包但存在由同一官方源码构建且可运行的干净产物时，可以制作离线 ZIP；附带：
   - `安装说明.txt`
   - 原项目 `LICENSE`
   - 版本、架构、来源提交或 Release 信息
   - SHA-256 校验文件
3. 离线包只含运行程序、必须依赖、许可证和说明。强制排除：
   - `settings.json`、`mcpRuntime*.json`、MCP Bearer 凭据
   - API Key、供应商配置、浏览器数据和登录状态
   - 用户项目、工作区、缓存、日志、生成媒体和聊天记录
4. 当前 Agent 能向用户交付文件时，输出到用户指定目录；未指定时使用与当前工作区同级的可读目录 `Toonflow离线安装包/<版本>/`。例如工作区为 `C:\项目\wow`，默认输出到 `C:\项目\Toonflow离线安装包\<版本>\`。
5. 没有可验证的官方安装包或可重现构建产物时停止，说明缺少什么；不得把正在使用且含个人数据的整个安装目录直接压缩给别人。

## MCP 接入与验收

1. 启动客户端并打开目标项目。
2. 在“设置 → MCP”启用服务；使用界面实际显示的地址和 Bearer 凭据。
3. 将凭据写入客户端的用户级 MCP 配置，不写入项目仓库。
4. 重新加载外部 Agent 的 MCP 客户端。
5. 调用 `getAppState`，确认连接、目录和画布；再用 `getCanvas` 做只读验证。
6. 验收成功后转入 `mcp-canvas-runtime/SKILL.md`。安装过程中不启动媒体生成。

## 对话交付回执

无论成功或失败，都必须在对话框中报告：

- 实际采用在线安装还是离线安装；
- 官方来源 URL、版本和 Windows 架构；
- 下载的原始安装程序绝对路径；
- 整理后的离线包绝对路径；尚未制作时明确写“尚未生成”；
- `SHA256SUMS.txt` 或等效校验文件绝对路径；
- 客户端实际安装位置；
- MCP 地址只报告主机和端口，不回显 Bearer Token；
- `getAppState` 与 `getCanvas` 是否验证成功。

不得只回复“安装完成”而省略文件位置，也不得把源码目录、正在使用的程序目录或单个原始安装程序称为已经整理好的离线包。
